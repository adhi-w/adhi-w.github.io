# Adhi Widagdo - CV and portfolio

A static, multi-page website for GitHub Pages. Root HTML, responsive images, icons, and PDF downloads are committed directly; visitors do not need a framework, external fonts, or a build service.

## Site structure

- `index.html`: overview, credited portrait, and three featured research projects.
- `cv.html`: detailed experience, education, technical toolkit, and full-CV printing.
- `resume-xr.html` and `resume-research.html`: one-page resume previews and PDF downloads.
- `projects.html`: searchable portfolio of 28 projects.
- `research.html`: selected publications, preprints, awards, and posters.
- `contact.html`: LinkedIn and an obfuscated contact address.
- `portfolio-details-*.html`: case studies at stable URLs, with manual image galleries.

The galleries include all 155 project images. Thumbnails, buttons, arrow keys, and touch gestures select images; there is no autoplay. Originals remain available through explicit image links.

## Editable sources

- `assets/content/projects.json`: project copy, metadata, images, captions, and source links.
- `scripts/profile_content.py`: career content shared by the detailed CV, resume pages, and PDF exports.
- `scripts/build_site.py`: shared templates and overview/research/contact copy.
- `assets/css/site.css` and `assets/js/site.js`: layout, print styles, and interactions.
- `assets/content/images.json`: responsive image manifest generated by the image utility.

Python 3.12 or newer is required. The HTML generator uses the standard library. Install the optional image/PDF authoring dependencies when regenerating those assets:

```sh
python -m pip install -r requirements.txt
```

After editing page content:

```sh
python scripts/build_site.py
python scripts/check_site.py
```

After changing resume content, also regenerate the downloads:

```sh
python scripts/build_resumes.py
```

The PDF builder verifies that each resume is one A4 page. Review rendered PDFs after substantive edits. Browser print settings can vary; the downloads provide a fixed layout.

To retain readable four-space HTML formatting, use your editor or the optional helper with js-beautify 1.15.4 installed outside the deployable site:

```sh
node scripts/format_html.cjs /path/to/node_modules/js-beautify
```

## Images and attribution

Original portfolio images and portrait sources are retained. `scripts/optimize_images.py` produces thumbnail, card, and full WebP variants without upscaling or changing the originals. The inactive passport-photo source is retained for reference but has no generated variants.

```sh
python scripts/optimize_images.py
python scripts/build_icons.py
python scripts/build_site.py
python scripts/check_site.py
```

`ProfilePicture.jpg` was photographed by **Heikki Nenonen**. The supplied permission requires naming the photographer whenever the photograph is used, including cropped or optimized copies. Keep the visible portrait credit in any reuse; see `assets/img/PHOTO-CREDITS.txt`.

The favicon exporter uses `assets/img/monogram.svg` to create PNG icons, an Apple touch icon, and the multi-resolution root `favicon.ico`. Filenames use exact casing for GitHub Pages.

## Preview and verification

```sh
python -m http.server 8765 --bind 127.0.0.1
```

Open `http://127.0.0.1:8765/`. Local HTTP is preferable to opening HTML files directly, especially when checking favicons. Review desktop/mobile layouts, full-CV pagination, and browser print previews before publishing.

Optional DOM checks use Node.js and jsdom 26, installed outside the site:

```sh
node scripts/check_interactions.cjs /path/to/node_modules/jsdom
```

These check navigation, search/filtering, every gallery image, keyboard/touch controls, print actions, email activation, motion preferences, and reduced-motion behavior. They do not replace browser visual inspection. Static and DOM checks passed for the current update; the PDF resumes were visually reviewed. Browser visual QA was unavailable because no browser was connected.

## Repository hygiene

`.gitignore` excludes Python caches/environments, Node dependencies, editor/OS files, logs, preview/test output, local environment variables, and private working notes. The local LinkedIn draft and editorial records in `docs/` are intentionally untracked. They can remain on the author's computer without entering Git or a GitHub Pages deployment.

Keep the generated root HTML, WebP files, favicons, sitemap, and PDF downloads tracked: GitHub Pages serves them directly. Source images and build scripts are retained for reproducibility. Retired template styles/scripts, vendor packages, reference portraits, old decorative images, and superseded icons have been removed.

## Maintenance

- Update forthcoming publication wording when publication/presentation status is confirmed. ACM Multimedia 2026 is scheduled for 10-14 November 2026.
- Keep unpublished research descriptions high-level. Do not place private methods or personal notes in HTML comments or public source files.
- Preserve photographer attribution, original project images, manual gallery controls, and exact-case links.
- Completed degrees omit dates and GPAs. Current doctoral-study dates and employment dates are maintained separately in the shared career source.
- The motion-capture project date, humanoid dimensions, and disputed HuroCup All Round result remain omitted because the historical sources conflict.

The site uses a navy theme, meteor effects, and a neon portrait contour. The footer motion control remembers its state; system reduced-motion preferences are respected. The public email is displayed with `[dot]` and `[at]`, and the email-app URL is assembled only after a click. This reduces basic scraping but does not remove previously published addresses from Git history or third-party copies.
